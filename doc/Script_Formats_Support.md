# Lambda Script Source Formatters

`lambda.doc.misc` provides **AsciiDoc, troff/man, Typst, EML, vCard, and
iCalendar** writers. These are shipped Lambda Script modules (D7.2.4).
The prose writers consume normalized Mark Doc; record writers consume the
existing email/contact/calendar maps. Content normalization follows
S2.6.1v2 and S2.6.2–S2.6.5.

**Status (2026-10-15):** initial profiles. Native build and package compilation
pass. Dedicated round-trip checks now run: EML/VCF/ICS pass; AsciiDoc, man,
and Typst fail structural readback checks in their existing readers. Native
tool conformance remains unverified. See [verification](#verification).

## API

```lambda
import writers: lambda.doc.misc
let document = parse("# Title\n\nSome **text**.", "markdown")^
let report = writers.format_report(document, {type:"asciidoc"})^
let source = writers.typst(document)^
let manual = writers.man(document, {title:"LAMBDA", section:"1"})^
```

| Function | Result |
|---|---|
| `format_report(value, options = null)` | `{text, diagnostics}` |
| `format(value, options = null)` | Serialized source string |
| `format_file(path, options = null)` | Reads a file, then serializes it |
| `asciidoc`, `man`, `typst`, `eml`, `vcf`, `ics` | Convenience functions with `(value, options = null)` |

Options are `type` (default `asciidoc`) and `loss` (`error`, default, or
`allow`). Man also accepts `title`, `section`, `date`, `source`, and `manual`
for `.TH`; default title is `meta.title` or `UNTITLED`, section `1`, and the
remaining arguments are empty. `format_file` adds `input_type` (default
`auto`) and `input_flavor` (default empty). Unknown options are errors.

`format_report` returns text even when there are losses. Diagnostics contain
`code`, `severity`, `element`, and `message`. `format` raises on the first
diagnostic unless `loss:"allow"` is selected. Invalid structures, forbidden
control characters, and unsupported transfer encodings remain errors in both
modes. The writers do not implement full RFC or native-tool validation.

The built-in formatter and CLI use the same package:

```lambda
let document = parse("# Title\n\nText.", "markdown")^
format(document, {type:"asciidoc", loss:"error"})^
```

```bash
./lambda.exe convert guide.md -t asciidoc -o guide.adoc
./lambda.exe convert guide.md -t man -o guide.1
./lambda.exe convert guide.md -t typst -o guide.typ
./lambda.exe convert contacts.vcf -f vcf -t vcf -o exported.vcf
./lambda.exe convert events.ics -f ics -t ics -o exported.ics
./lambda.exe convert message.eml -f eml -t eml -o exported.eml
```

Output aliases are `adoc`, `troff`, `vcard`, `ical`, and `icalendar`.
CLI `--loss error|allow` covers these writers and wiki writers. File output
detects `.adoc/.asciidoc/.asc`, `.man/.1`–`.9`, `.typ/.typst`, `.eml`,
`.vcf/.vcard`, and `.ics/.ical`; it uses strict defaults. For permissive file
output, call the package formatter first and write its resulting string as
`text`. No native C++ emission rules are added (D7.1.1); the lower
runtime-free `format_data` API refuses these targets.

## Prose coverage

The three writers share a traversal for headings, paragraphs, emphasis, code,
nested lists, definition lists, links, images, quotes, rules, breaks, and
tables. AsciiDoc maps supported block IDs; Typst maps heading/table labels.
Tables support cell spans in
those two formats. AsciiDoc maps binary checkboxes. Man produces `.TH`,
`.SH/.SS`, `.PP`, `.IP/.TP`, `.RS/.RE`, font escapes, `.nf/.fi`, and `tbl`
tables, with source text protected against roff request interpretation.

AsciiDoc reserves `= Title` for `meta.title`; body h1 starts at `==`, and
headings deeper than its five section levels are diagnosed. Its existing
reader's heading/title handling does not yet guarantee a structural round trip.

Loss diagnostics cover unsupported attributes/elements, richer task states
and progress, footnotes/citations/math, advanced figure/layout semantics,
target-specific text effects, man images/table spans/headings deeper than two
levels, and raw source belonging to another syntax. The existing Typst reader
does not interpret every function call generated by the writer; source output
and native Typst compilation are separate capabilities. Formatting does not
run Asciidoctor, groff, or Typst, or fetch resources.

## vCard

```lambda
import writers: lambda.doc.misc
writers.vcf({
    full_name:"Ada Example",
    name:{family:"Example", given:"Ada"},
    email:["ada@example.com", "ada@work.example"],
    phone:"+1-555-0100",
    address:{street:"1 Main Street", city:"Singapore", country:"Singapore"},
    note:"First line\nSecond line"
})^
```

The writer accepts one contact, an array of contacts, or `{contacts:[...]}`.
New contacts default to version 4.0; retained versions 3.0 and 4.0 are
supported. Recognized fields are `version`, `full_name`, `name`, `email`,
`phone`, `organization`, `title`, `note`, `url`, `birthday`, and `address`.
The `name` fields are `family`, `given`, `additional`, `prefix`, and `suffix`;
address fields are `po_box`, `extended`, `street`, `city`, `state`,
`postal_code`, and `country`. Scalar fields may use arrays for repeats;
individual fields can use `{value, parameters}`.

Retained source takes precedence:

1. `entries`: ordered `{name, value, parameters?, parameter_source?}` records.
   Values default to already escaped wire text (`raw:true`). Repeats and
   parameters are preserved. `parameter_source`, when present, retains exact
   original parameter quoting and repeats; remove it when editing the
   `parameters` map. A semantic entry may set `raw:false` for TEXT/parameter
   escaping.
2. `properties`: a map of wire values, including arrays for repeats.
3. Convenience fields above, when neither source view is present.

Convenience fields do not override retained entries. Edit the entries to
preserve source details, or remove `entries` and `properties` to author from
fields. FN is required; version 3.0 also requires N. Missing required fields
produce diagnostics. Unknown fields are reported rather than silently dropped.

## iCalendar

```lambda
import writers: lambda.doc.misc
writers.ics({components:[{
    type:"VEVENT",
    uid:"meeting-1@example.com",
    stamp:"20261015T000000Z",
    start_time:{year:2026, month:10, day:16, hour:9, minute:0, second:0, timezone:"UTC"},
    end_time:{year:2026, month:10, day:16, hour:10, minute:0, second:0, timezone:"UTC"},
    summary:"Planning meeting",
    description:"Discuss the next release"
}]})^
```

Calendar maps use `version`, `product_id`, `calendar_scale`, `method`, and
`components`. VERSION is 2.0; a missing PRODID uses the formatter's product
identifier. Component fields include `type`, `uid`, `stamp` (DTSTAMP),
`summary`, `description`, `location`, `status`, `priority`, `organizer`,
`attendee`, `start_time`, `end_time`, and `duration`. Date-part maps emit
DATE or floating/UTC/TZID DATE-TIME. Duration maps accept weeks, or
days/hours/minutes/seconds. Other supported field names appear in the
[implementation contract](../vibe/input/Input_Script_Formats.md).

The same `entries` → `properties` → fields precedence applies. Nested component
maps in ordered entries preserve VALARM/VTIMEZONE structure; newly authored
component maps can instead contain `components` arrays. RRULE and extension
properties can be supplied as wire entries. Required properties are checked
for common components, but recurrence and timezone semantics are not evaluated.
The writer does not invent UIDs or dates.

VCF and ICS use CRLF, semantic TEXT escaping, quoted parameters, and folding
within 75 UTF-8 octets without splitting a scalar. Their readers now unfold
whole logical lines and retain empty property values. Original parameter text
preserves distinctions unavailable in the convenience parameter map.

## EML and MIME

```lambda
import writers: lambda.doc.misc
writers.eml({
    from:{name:"Ada Example", address:"ada@example.com"},
    to:["team@example.com"],
    date:"Thu, 15 Oct 2026 09:00:00 +0000",
    subject:"Release notes",
    body:{type:"multipart/alternative", parts:[
        {type:"text/plain; charset=UTF-8", content:"The release is ready.\n"},
        {type:"text/html; charset=UTF-8", content:"<p>The release is ready.</p>"}
    ]}
})^
```

Headers may be a `headers` map or ordered `header_entries` array; ordered
entries take precedence and preserve repeated headers. Missing common headers
can be supplied as `from`, `to`, `cc`, `bcc`, `reply_to`, `subject`, `date`, and
`message_id`. Structured mailboxes use `{name, address}`. FROM and DATE are
required; missing values are diagnosed.

The reader retains authoritative `raw_body` alongside the display `body`.
Keeping it preserves original MIME parts and attachments. Remove `raw_body`
to rebuild a message. A string `body` with a retained transfer-encoding header
is also wire content; remove that header or use a part map to supply new plain
text. Rebuilding only a multipart message's display HTML diagnoses attachment
loss. The reader's `addresses` and `mime` views are derived from the headers
and `raw_body`; the writer ignores them, so edit those instead.

New part maps accept `content` (string, binary, or HTML element),
`content_type`/`type`, `encoding`, `headers`, `parts`, `filename`, `content_id`,
and `disposition`. Top-level `attachments` builds multipart/mixed. Content
defaults to Base64; quoted-printable and checked 7bit/8bit text are supported.
UTF-8 subjects/display names use encoded words; filenames use extended MIME
parameters. Header control characters are rejected, header folding occurs at
whitespace, and generated boundaries avoid serialized parts.

Fresh text supports UTF-8/US-ASCII. Other charset conversion, SMTPUTF8
structured headers, exceptionally long filename parameter continuations, and
complete mail-client interoperability remain outside this initial profile.
No email is sent by these functions.

## Verification

Run from the repository root:

```bash
python3 test/script_format_roundtrip.py --report temp/script-format-roundtrip.json
./test/test_lambda_gtest.exe --gtest_filter='*doc_misc_roundtrip*'
```

The Python suite is registered in the `input` baseline through
`test/run_script_format_roundtrip.js`. It checks the package, built-in
`format`, automatic file `output`, and CLI paths. Record comparisons retain
duplicate map keys and ordered entries (D2.6.5v3); prose comparisons retain
element names, attributes, whitespace, and content, allowing transparent
parser spans and adjacent text chunk merging (S2.6.4).

Current results: **31/43 checks pass**. All 16 EML/VCF/ICS round trips preserve
the parsed model and produce identical source on a second write. Fifteen
alias checks pass. The 12 prose checks fail, across all four paths:

- AsciiDoc reads body section `==` as h2 instead of h1 and misreads listing attributes.
- Man reads `.TH` as a body heading, misses next-line `.SH/.SS` text, and
  misreads bracketed font and roff text escapes.
- Typst reads generated `text`, `strong`, `emph`, and `raw` calls as literal source.

These failures remain ordinary failing assertions. The suite currently exits
with failure; they are not skipped or accepted as golden output.

The Lambda golden test separately passes 31 checks for authored contact,
event/alarm, and MIME values, all six built-in routes, strict loss handling,
and invalid inputs. It passes under the interpreter, JIT, and JIT with
`LAMBDA_GC_FORCE_EVERY=1 LAMBDA_GC_POISON_FREED=1` (D5.3.3).
Fixtures also cover Unicode folding, empty/repeated
fields, quoted parameters, multiple vCards, VTIMEZONE/VTODO/VALARM, MIME
alternatives, and binary attachment source retention. These checks establish
Lambda reader/writer behavior, not external tool or mail-client conformance.

See the [implementation contract and syntax references](../vibe/input/Input_Script_Formats.md).
