# Node.js Official Test Skip List
#
# Tests listed here are permanently skipped because they require features
# that are fundamentally unavailable in the Lambda JS engine.
#
# Format: test-filename.js  # reason
# Lines starting with # are comments. Blank lines are ignored.
#
# Categories:
#   [fork]       Uses child_process.fork() which spawns a Node binary
#   [http2]      Requires Node.js HTTP/2/nghttp2 support
#   [dgram]      Requires Node.js UDP/datagram socket support
#   [wasi]       Requires Node.js WASI support
#   [icu]        Requires full ICU internationalization support
#   [sea]        Requires Node.js Single Executable Application support
#   [snapshot]   Requires V8 snapshot building API
#   [native]     Requires native C++ addons / node-gyp
#   [hang]       Known to hang (infinite loop, unimplemented event loop feature)
#   [crash]      Known to crash LambdaJS during default official-test runs
#   [timeout]    Known to hit the runner timeout or require unavailable signals
#   [spawn-node] Spawns 'node' binary with Node-specific CLI flags
#   [unimplemented] Requires a Node feature not implemented in LambdaJS yet
#

# --- Unimplemented LambdaJS feature areas ---
#
# TLS existing-socket attachment is temporarily quarantined. LambdaJS now has a
# minimal mbedTLS/libuv transport, but these fixtures require a cross-module
# net.Socket adoption API: TLS must take over an already-connected net.Socket,
# preserve any encrypted bytes net has already read, and own subsequent
# read/write/backpressure ordering. Until that handoff exists, TLS-local shims
# drop data or miss interleaved records.
test-tls-interleave.js                      # [unimplemented] needs the retired net socket transport for TLS record interleaving
#
# TLSv1.0/TLSv1.1 protocol negotiation is intentionally unsupported in
# Lambda Node for now. The current mbedTLS 3.x build only exposes TLS 1.2 and
# TLS 1.3 (`MBEDTLS_SSL_VERSION_TLS1_2` / `MBEDTLS_SSL_VERSION_TLS1_3`), while
# this Node fixture imports the full min/max protocol matrix and expects
# legacy TLSv1.0/TLSv1.1 success and error behavior. Until Lambda Node adopts a
# different TLS backend/build with legacy protocol support, skip the CLI wrapper
# instead of adding fake negotiation shims.
test-tls-cli-max-version-1.3.js             # [unimplemented] requires TLSv1.0/TLSv1.1 min/max matrix behavior unavailable in current mbedTLS build
