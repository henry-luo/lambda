# DocBook fixtures

These small DocBook 5.2 documents exercise the native `lambda.doc.docbook`
package's initial HTML profile. `article.xml`, `book.xml`, `tables.xml`,
`notes.xml`, `lists.xml`, `book_notes.xml`, `inlines.xml`, and `verbatim.xml` are authored
Lambda fixtures. `media.xml` and
`sample.svg` exercise captured local resources separately from transformation
parity. Functional/procedural goldens live in `test/lambda/docbook/`.

`showcase.xml` is a larger, original DocBook book that can be opened directly:

```sh
./lambda.exe view test/input/docbook/showcase.xml
```

It includes chapters, contents, lists, a CALS table, a verbatim journal entry,
cross-references and a footnote. XML roots in the DocBook namespace are
presented through `lambda.doc.docbook`; selecting the file in `lambda view`
also offers the rendered document and its original XML source. Viewing reads
the source and resolves package CSS/captured media without writing an export.

`expected/` contains body markup generated by the official xslTNG 2.8.5
distribution at commit `b26a7c42445b5aae1e3e6cda866513427b2b061c` with
Saxon-HE 12.10. The default head is tested separately through export assertions.
Upstream attribution and its MIT notice are retained in
[`UPSTREAM.md`](../../../lmd/package/doc/docbook/UPSTREAM.md) and
[`LICENSE.xsltng`](../../../lmd/package/doc/docbook/LICENSE.xsltng).

Run `python3 test/docbook_reference_check.py` and the same command with
`--chunked` for structural comparisons and publication-integrity checks.
Use `--refresh` only to regenerate results with the pinned official processor;
that step needs the verified distribution and Java. All temporary output
stays under `temp/`.
