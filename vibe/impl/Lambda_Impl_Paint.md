# Lambda Paint — Implementation

**Design:** [Lambda Paint Package](../Lambda_Pkg_Paint.md) (PT#) and [Radiant Paint Engine](../../../radiant/vibe/Radiant_Design_Paint_Engine.md) (PE#). The user asked to proceed to implementation on 2026-11-09. This record tracks delivery, decisions taken while implementing, and evidence.

## Decisions taken during implementation

- **Bridge in the `radiant` host module (2026-11-09).** System functions are enumerated in lambda-input's `lambda.h`, which Lambda work must not edit. The bridge is therefore a set of `radiant.paint_*` functions in `lambda/module/radiant/radiant_paint_adapter.cpp`, registered in the `radiant` module table. This settles PT-O3 (PT15).
- **The runtime never calls the engine.** The runtime boundary DSO must not import Radiant symbols (`utils/check_module_boundary.py`). `lambda.image`'s brush therefore migrates at the package level (PT13): `lambda.paint` produces coverage through `radiant.paint_*`, and `image_edit.cpp` composites a supplied coverage.
- **Dab falloff profiles.** The dab table gains a `profile` column (32): `0` is libmypaint's two-segment falloff over squared distance; `1` is the linear cone with a flat core that `lambda.image`'s brush uses. That makes 33 columns in `PAINT_DAB_V1`.
- **`var`-parameter procedures move to M1.** M0 needs only the pure forms (PT7). The general `var` system-procedure form arrives with the interactive session.
- **Dab layout grows to 34 columns before publication (M1).** Column 33 is `blend` (`PaintBlend`). No layout had been published, so `PAINT_DAB_LAYOUT_VERSION` stays 1.
- **Canvas rectangle write is its own DOM operation (M1d).** DOM operations have a fixed arity, so `dom.set_canvas_pixels_rect(canvas, pixels, rect)` sits beside `dom.set_canvas_pixels` instead of adding an options argument, which would have broken existing two-argument callers. The rectangle uses the engine's `[x0, y0, x1, y1]` form, so a `paint_present` rect and its pixels pass straight through.
- **Pens are pointer 2 (M1e).** The mouse keeps `pointerId` 1, and a pen in proximity is 2. Pointer capture used to accept only id 1; it now follows the pointer that last pressed, so `setPointerCapture(evt.pointerId)` works for a pen.
- **Coalesced samples ride on the event (M1e).** The event host attaches the samples to each native pointer event as a hidden `__pointer_samples` array, the same hidden-slot pattern as `__target_ranges`. `dom.pointer_samples` reads it. Sample times are the event's `timeStamp` minus each sample's age on the native clock, so the result does not depend on which clock produced the native event.
- **Session API (M1f).** The interactive session is a value in `lmd/package/paint/session.ls`. Its frame function is `frame`, not the sketch's `present`, which already names layer conversion. History entries cost the bytes of the tiles their stroke forked. One stroke paints at a time; a second pointer's press commits the first stroke. Recorded in PT10's implementation note.
- **Demo zoom by CSS geometry (M1f).** The canvas bitmap is the layer. Zoom and pan change the sheet's `left`, `top`, `width` and `height`, never a transform, so PE7's region repaint still applies. This caps canvases at the 4096-px upload limit until the viewport-sized presentation of PT10 lands.
- **Sample times may be negative (M1f).** `dom.pointer_samples` times are on the `evt.timeStamp` clock. Samples coalesced just after the time origin can precede it, so the stroke validator accepts any finite time within ±10⁹ s. Only differences matter to the dynamics.
- **Stored tiles are a bridge blob (M1g).** Typed-array-to-bytes conversion in Lambda would cost one list item per sample, so the paint bridge encodes and decodes a layer's tiles natively (`LPT1`, little-endian). A general typed-array byte conversion would be a system function, and those are enumerated in lambda-input's `lambda.h`.
- **PNG previews through system functions (M1g).** `preview.png`, `thumbnail.png` and `export_png` use `lambda.sys.image_raster` and `lambda.sys.image_encode` directly, so `lambda.paint` keeps not importing `lambda.image` (PT13).
- **Tip lists can be stacks (M1i).** A Lambda array literal of equal-size planes, such as `[tip]`, coalesces into one `(k, h, w)` numeric array, so `radiant.paint_dabs` accepts `tips` as a list of planes or as such a stack. Paper must be one `(h, w)` plane.
- **Angle jitter is keyed by position (M1i).** A round brush's per-dab rotation comes from the dab's position, not its index, so a stroke split into batches still paints exactly the whole stroke.
- **Rectangle repaint uses presentation damage (M1d).** Radiant already repaints regions for paint-only writes (presentation damage). The canvas notes its placement while it is recorded, and a rectangle write marks the mapped region as presentation damage. A canvas drawn under a transform, a filter or an offscreen capture falls back to a full repaint.

- **2026-11-11 — PT7 package surface.** The user chose to follow PT7 fully.
  - **Package.** `paint.stroke(var layer, brush, colour, points, options)` and `paint.feed(var session, pointer, samples)` are `pn`s returning `{rect, work}`; `paint.stroke_step` is the pure per-batch form (`render`/`render_pass` wait on PT16). `stroke.ls` exposes the shared pure pieces (`batch`, `unpainted`, `washes`, `continued`, `wash`), and both procedures call `radiant.paint_stroke` on their own place. A wash composites over the stroke's source, so its preview is a new layer on both forms.
  - **Why the native is called directly.** A member place such as `s.layer` passed to a Lambda `pn` is borrowed in place only when the callee has one `var` parameter and no other parameter that may hold a container (MVP `exclusive_place`; T0 `snapshot_home`). Otherwise the leaf is snapshotted, so every write copies. The native path's alias rule (D7.6.3, `var_alias_capture_mask`) has no such limit, so `feed` writes `s.layer` through `radiant.paint_stroke` itself. A probe that fed 5 batches over one tile copied it once and wrote it in place 4 times on interp, jit and auto.
  - **T0 fix.** T0 refused every call to a procedure with `var` parameters and default parameters (`pn bump(var m, by = 1)` failed with E501 under `interp`). `ast_direct_call_var_parameter_entries` demanded exact arity; it now admits omitted optional parameters, which take their defaults in the callee as for any direct call, and still refuses an omitted `var` argument.
