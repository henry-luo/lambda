# Proposal: close CSS selector and property gaps in Radiant

**Status:** In progress (P0/P1 selector and cascade work; P3 text fixes)  
**Date:** 2026-10-02  
**Baseline:** [HTML, CSS and SVG Support](../../doc/HTML_CSS_SVG_Support.md) §§3, 5–7, 18, assessed 2026-09-28  
**Scope:** Stylesheet selectors, their DOM-query counterpart, and CSS properties reported as partial, parsed only, or unrecognized. At-rules and value syntax enter the plan where a selector or property depends on them.  
**Authority:** This is an implementation proposal, not a CSS ruling. The report is an observed-support inventory. Radiant allocation and ownership must continue to follow **D4.5.1v4**; a change to that contract needs a separate design decision. No CSS-specific S#/D# ruling was found for the choices below.

## Goal and completion rule

Make a supported selector choose the right elements and cascade priority in both stylesheets and DOM queries. Make a supported property survive parsing, cascade, computed-value resolution, and its relevant layout, paint, animation, or interaction consumer. A parsed name without a visible or queryable effect remains *parsed only*. An invalid value detected at parse time must leave an earlier valid declaration eligible; a value made invalid by later substitution must use the computed-value fallback. Neither case may silently become zero or a raw pixel length.

The 2026-09-28 report counts 342 recognized properties: 244 effective, 43 partial, and 55 parsed only. Those are the baseline, not a claim that every recognized value is valid. Recount the categories after each delivery; do not close a row on the strength of parser acceptance alone.

Standards checks for these shared rules: [Selectors Level 4](https://drafts.csswg.org/selectors/) §§13.3.1, 15–16.1 (filtered siblings, specificity, selector-list recovery), [CSS Cascade Level 5](https://drafts.csswg.org/css-cascade-5/) §4 (value stages), and [CSS Values Level 5](https://drafts.csswg.org/css-values-5/) on property replacement and invalid substitution. These editor's drafts guide test expectations; this proposal does not add a Lambda-specific ruling.

## Implementation boundaries

| Stage | Existing owner | Work in this proposal |
|---|---|---|
| Selector grammar and specificity | `lambda/input/css/css_parser.cpp`, `selector_matcher.cpp` | Preserve namespace and relative-selector structure, reject invalid selector lists according to their grammar, calculate specificity for every pseudo-class and pseudo-element. |
| Stylesheet application | `radiant/css_cascade.cpp`, `lambda/input/css/css_style_node.cpp` | Use the greatest specificity of all matching selectors for each applicable target; preserve origin, importance, order, and separate pseudo-element destinations. |
| Property registry and value validation | `lambda/input/css/css_properties.cpp`, CSS value parser | Register missing names and aliases, validate each property's grammar, and share longhand/shorthand metadata. Do not mark a name effective merely because it is registered. |
| Computed style and consumers | `radiant/resolve_css_style.cpp`, `radiant/view.hpp`, layout, render, and interaction modules | Resolve units and inheritance, store state with the correct lifetime, then consume it in layout/paint/interaction. Keep scratch and retained values within **D4.5.1v4** ownership rules. |
| Observable surfaces | DOM query APIs, CSSOM, `lambda layout`, `lambda render`, `lambda view` | Keep stylesheet matching and query matching consistent where their contexts agree; verify computed output and visual effect separately. |

Before implementation, attach one minimal reproducer to each report row and confirm its current failure. The support report and older CSS design/progress docs describe different snapshots; a row that already works should be closed with evidence rather than reimplemented. In particular, `selector_matcher_matches_group()` already selects the strongest match for a group, while `radiant/css_cascade.cpp::apply_rule_to_element()` records the first matching ordinary selector. That gives a concrete first fix without replacing the matcher.

## Delivery plan

Each phase is independently reviewable. The ordering follows shared machinery first, then features that need new state or render paths.

### P0 — make CSS failure and cascade behavior reliable

1. Add focused cases for every selector-list and declaration failure in this plan. Fix the stylesheet group's first-match specificity path, the incomplete pseudo-class/pseudo-element specificity calculation, and invalid selector-list retention. Include the pseudo-class plus argument specificity of `:nth-child(... of S)` and `:nth-last-child(... of S)`. Keep forgiving-list recovery limited to `:is()` and `:where()`; an invalid ordinary rule selector must not partly apply.
2. Normalize case-insensitive CSS keywords at the parser boundary for pseudo-class, at-rule, and property names, while preserving case-sensitive IDs, classes, custom properties, and values where required.
3. Repair the reported inline versus stylesheet `!important` origin inversion, `width`/`height: initial|unset` becoming zero, and `all` resetting only fonts. Make invalid values, including unknown units/functions, fail before a declaration can displace a valid earlier one. This is necessary for later property work to produce trustworthy results.
4. Keep shorthand expansion and `var()` substitution on one path. Verify cycle fallback, declaration-site custom-property inheritance, and invalid-at-computed-value handling before broadening new shorthands.

**Exit:** A selector group gives the same winning selector in the matcher and stylesheet cascade; invalid selectors and parse-time invalid declarations cannot broaden a match or displace an earlier valid property; the existing cascade-memory gate remains stable.

**Memory gate, 2026-10-03:** The Bootstrap kitchen-sink fixture binds one additional canonical recipe after the selector/cascade corrections. Its 251 entries and 3305 payload references are identical before and after a clean recascade, with all entries still bound and no cold entries. The structural ceiling in `test/css_cascade_memory_baseline.tsv` now records that measured semantic change; the other fixture ceilings are unchanged.

`@layer a, b;` terminates at its semicolon instead of consuming the next style rule (`CssEngineParserTest.LayerOrderStatementPreservesFollowingRule`). Layer declarations now rank before specificity, with `!important` reversing layer order. The cascade registry preserves named, nested and anonymous layer order across stylesheets and layered imports, and `revert-layer` rolls a property back to the next eligible layer or origin. `all: revert-layer` now competes with each longhand before rollback; its winning layer discards same-layer longhands (`CssStyleApplicationTest.AllRevertLayerRollsBackLonghandsInSameLayer`, `RenderOutputParity.CascadeLayersRevertAndNestedOrder`). Imported sheets apply at their `@import` source position; `layer()`, `supports()` and media modifiers are parsed and evaluated, and late imports are rejected (`CssEngineParserTest.ImportConditionsAndLayerNameArePreserved`, `ImportPlacementRespectsLayerStatements`, `RenderOutputParity.CascadeLayersOrderNormalAndImportantDeclarations`, `CascadeLayersShareOrderAcrossStylesheets`, `ImportedRulesKeepTheirSourcePosition`). `all: inherit` now reaches the common computed-value paths, with display resolved before layout and non-inherited values applied before explicit declarations. `RenderOutputParity.AllInheritUsesParentComputedBoxAndTextValues` checks display, dimensions, padding, border, background and color; `AllInheritOpacityAndAllRevertPaint` checks nested opacity and author-origin rollback in SVG. Other property consumers still need a visual audit. Logical spacing inheritance copies the mapped physical sides instead of zeroing them, and CSS-wide simple keywords copy the parent's computed value or the initial value. The scratch registry and retained declaration rank follow **D4.5.1v4**.

Logical and physical side declarations now compare by the full cascade order. Direct used-value candidates use `css_declaration_cascade_compare()`, while layer-bearing style passes assign an exact relative rank before storing per-side values; this avoids the old packed priority's omission of layers. `RenderOutputParity.LogicalAndPhysicalBordersRespectLayerOrder` checks normal and reversed important layer order. The style-pass rank array uses scratch ownership under **D4.5.1v4**.

The report's neighboring at-rule gaps need their own acceptance cases where they gate this work: `@supports selector()` and declaration tests must use the completed selector/property validators; `@namespace` is needed for qualified selectors; nested style rules and `@scope` need selector-context handling; `@container` needs the P3 container state; `@property` needs registered custom-property validation. Cascade layers and `revert-layer` affect which declaration wins even when matching and property resolution are correct. Track those as dependencies rather than crediting selector or property coverage for merely parsing the at-rule.

Nested style rules now parse recursively and enter both the normal and allocation-fallback cascade paths. Each relative selector branch expands its `&` against the complete parent list through `:is()`, preserving the maximum parent specificity without multiplying selector combinations. Direct declarations after child rules become ordered `CSSNestedDeclarations` runs; nested `@media` and `@supports` retain the parent selector for their declarations and relative child rules. Standalone `&` resolves through `:scope` in stylesheet and DOM selector parsing. CSSOM serializes nested rules and declaration runs in source order; a nested declaration wrapper reads `cssText` from the live rule, and changing an outer rule's `selectorText` rebinds descendant selectors before recascade. `CssEngineParserTest.NestedRulesRetainDepthAndAuthoredSelector`, `NestedDeclarationsKeepInterleavedRuleOrder`, `TopLevelNestingSelectorUsesScope`, `DomIntegrationTest.NestingSelectorUsesQueryScopeOutsideRules`, and `RenderOutputParity.NestedSelectorsPaintAcrossDepthAndPreserveSpecificity` cover parsing, scope, specificity, order and paint. `RenderOutputParity.NestedSelectorsRestyleAfterParentClassMutation` and `NestedCssomSerializesAndRebindsAfterSelectorMutation` verify live invalidation, serialization, and selector mutation; the WPT CSS Syntax `custom_property_rule_ambiguity` and `invalid_nested_rules` cases pass. This follows [CSS Nesting 1 §§3–6](https://drafts.csswg.org/css-nesting-1/) and retains rule spans in the stylesheet pool under **D4.5.1v4**. Nested `@container` and remaining CSSOM insertion and deletion cases remain open.

The DOM query variant of standalone `&` no longer frees a null authored-output buffer during selector expansion. The full `test_css_dom_integration.exe` run also exposed an old margin source-order fixture that fed raw string pointers to a typed value validator; it now builds parsed declarations and checks the winning value text. The expansion's temporary strings follow **D4.5.1v4**.

The `@media` condition parser now copies its source span so paired range operators retain their spacing. The evaluator uses the shared top-level condition splitter for `and`/`or`, compares one- and two-sided `width`/`height` ranges, evaluates known boolean features, and rejects unknown media types and malformed lengths. `aspect-ratio` and `resolution` now use the same numeric comparison path with strict ratio and resolution units; resolution reads the engine's configured device-pixel ratio, which is currently 1 for normal page loads. HTML PDF export selects print media before linked stylesheet discovery and cascade, while SVG/raster/view remain screen media. The media-condition cache key includes the selected medium. `CssEngineTest.MediaQueryRangeBooleanAndOrUseFeatureValues`, `MediaRatioAndResolutionUseTypedRangeValues`, and `MediaQueryPrintContextInvalidatesCachedResults` test direct evaluation; `RenderOutputParity.MediaRangeAndOrSelectVisibleRules` and `PdfPrintMediaSelectsRulesAndLinkedStylesheet` confirm screen and PDF paint. The condition scratch pool follows **D4.5.1v4**. Other media features, `@page`, page breaks, print styles in document transforms and nested frame media propagation remain open. Range/boolean semantics follow [Media Queries 4 §§2.4.2–2.4.3](https://drafts.csswg.org/mediaqueries-4/#mq-range-context), with ratio and resolution values defined in [Media Queries 4 §5](https://drafts.csswg.org/mediaqueries-4/#mf-dimensions).

The shared viewport-length converter now handles `vi`/`vb` and the `sv*`/`lv*`/`dv*` width, height, inline, block, min and max spellings in used widths and viewport-relative font sizes. Radiant has no retractable viewport UI, so the three viewport variants use the current viewport dimensions. Font-relative `cap` and `ic` use the font's cap metric and the water ideograph's advance with the specified fallbacks; `rlh` reads the root's line-height. `RenderOutputParity.FontAndViewportRelativeUnitsResolveUsedWidths` checks horizontal and vertical axes, root line-height, and font-relative paint without assuming one exact installed font. This follows [CSS Values 4 §6.1](https://drafts.csswg.org/css-values-4/#relative-lengths) and keeps the same relayout-owned computed state under **D4.5.1v4**. Container units, other property consumers, and font-affecting self-reference remain open.

Length-expression validation now parses the math value tree before a declaration enters the cascade. Unknown identifiers/functions and incompatible dimensions inside `calc()` cannot displace an earlier valid width; `CssEngineParserTest.InvalidSizeValuesDoNotEnterCascade` covers that boundary. The used-length resolver propagates unresolved operands instead of turning them into zero and evaluates numeric functions including trig, rounding strategies, modulus, absolute value, powers, roots, logarithms, and hypot; `RenderOutputParity.MathFunctionsAndInvalidCalcResolveUsedWidths` checks measured boxes and nested expressions. The parser and resolver share the math-token spelling helper instead of copying operator interpretation. These changes follow [CSS Values 4 §§10.1–10.9](https://drafts.csswg.org/css-values-4/#calc-notation) and retain the existing stylesheet and relayout ownership of **D4.5.1v4**. Computed-value substitution, angle-valued consumers, full infinity handling, and property grammars outside the length-expression set remain open.

`var()` now splices a matching space-separated value list into its surrounding list before `margin` or `padding` shorthand expansion. `CssEngineParserTest.SpacingShorthandsValidateTokensBeforeCascade` rejects unsupported units/functions and negative literal padding; `RenderOutputParity.CustomPropertyTokensExpandInsideSpacingShorthands` checks rendered token expansion, an overlong substitution falling back at computed-value time, and a parse-time invalid declaration leaving the earlier margin in force. `RenderOutputParity.CustomPropertyTokensExpandInsideRgbFunction` covers modern `rgb()` with a whole channel list or one substituted channel. The scratch substituted list lives in the relayout pool under **D4.5.1v4**. The substitution model follows [CSS Variables 1 §3](https://drafts.csswg.org/css-variables/#using-variables); comma-separated lists, other functions and the broader shorthand inventory remain open.

Early display resolution now applies custom-property substitution before deciding whether to create a box. The shared resolver covers both the dedicated `CSSVarRef` parser node and function nodes, including variables inside a multi-keyword `display` list; list grammar is checked after substitution. `RenderOutputParity.DisplayVariableControlsBoxGeneration` verifies `none` and `contents` without painting the host, and `DisplayVariableExpandsMultipleKeywords` verifies that two substituted keywords create a flex formatting context. Whole-value substitution avoids allocation, while nested list substitutions use a short-lived scratch pool and retain no pointers after it is destroyed, following **D4.5.1v4**. Cascade rollback keywords reached through a variable still need an origin/layer audit.

Grid `repeat()` now reads the space-separated track list inside its comma-delimited function argument. The previous consumer treated that list as one track, so even literal `repeat(2, 10px 20px)` fell back to implicit rows. The same flattened track traversal now serves fixed and automatic repeats; `RenderOutputParity.GridRepeatExpandsLiteralAndVariableTrackLists` checks four painted columns for literal, fixed `var()` and `auto-fill` `var()` lists. The resolved value and generated tracks retain their existing relayout ownership under **D4.5.1v4**. Other grid substitution forms and invalid track grammar remain to audit.

The spacing validator also takes the HTML parsing mode. Standards mode rejects a nonzero unitless `margin` or `padding`; quirks mode accepts it as px, including in nested stylesheet rules. The document mode now reaches inline declaration parsing and the stylesheet engine rather than relying on a context-free validator. `RenderOutputParity.UnitlessMarginRequiresQuirksMode` checks both routes and both modes; the previously regressed `min-content-negative-margin-crash` WPT sizing case returns to its browser geometry. The mode and value trees remain document/stylesheet owned under **D4.5.1v4**. This follows [CSS Values 4 Appendix C](https://drafts.csswg.org/css-values-4/#quirky-length) and [Quirks Mode §3.2](https://quirks.spec.whatwg.org/#the-unitless-length-quirk). Other properties accepting quirky lengths still need context-aware validation.

Percentage alpha in `rgb()` and `rgba()` now uses the same 0–255 destination scale as numeric alpha in both modern and comma syntax. `RenderOutputParity.RgbPercentageAlphaPaintsLikeNumericAlpha` checks all three against a white raster background. This follows [CSS Color 4 §4.2](https://drafts.csswg.org/css-color-4/#alpha-value) and leaves the computed color in relayout-owned style under **D4.5.1v4**. Root `text-align: match-parent` now computes to `start` for an RTL root, passing `text-align-match-parent-root-rtl`; the bidi line pass excludes boxless `display: contents` borders from its edge width, restoring all 145 `wpt-css-display` baseline cases.

One angle converter now feeds transforms, HSL hues, linear/conic gradient directions and `hue-rotate()`. `RenderOutputParity.AngleUnitsAgreeAcrossColorGradientAndFilter` compares degree, radian, gradian and turn forms in raster paint, including visibly distinct red/blue gradient sides and a cyan HSL hue. Unsupported dimension units no longer pass through those angle consumers as raw degrees. This follows [CSS Values 4 §6.1](https://drafts.csswg.org/css-values-4/#angles) and keeps gradient/filter values within their existing relayout-owned state under **D4.5.1v4**.

The shared scale argument resolver now converts percentages to unit factors for `scale()`, `scaleX()`, `scaleY()`, `scale3d()` and `scaleZ()` without changing number-only matrix arguments. `RenderOutputParity.PercentageScaleMatchesNumericTransform` checks that `scale(50%)` and `scale(0.5)` produce the same SVG matrix. This follows [CSS Transforms 2 §12](https://drafts.csswg.org/css-transforms-2/#transform-functions) and keeps the function list in relayout-owned transform state under **D4.5.1v4**. Individual transform properties remain in P5.

The transform-origin resolver now treats unitless zero as a valid length in both single- and multi-value forms. `RenderOutputParity.UnitlessZeroTransformOriginMatchesLengthZero` compares SVG matrices for `0 0` and `0px 0px`; the former previously left the default center origin in place. This follows [CSS Values 4 §6](https://drafts.csswg.org/css-values-4/#lengths) and keeps the origin in the relayout-owned transform property under **D4.5.1v4**.

`drop-shadow()` now sends named, functional and `currentColor` arguments through the shared computed-color resolver instead of reading only numeric color nodes. `RenderOutputParity.DropShadowUsesNamedAndCurrentColor` checks separate green and blue raster shadows while the source boxes remain red. Filter state remains relayout-owned under **D4.5.1v4**.

`hwb()` now shares hue, component and alpha parsing with HSL before converting whiteness and blackness to sRGB. When their sum reaches 100%, the result is achromatic with white divided by their sum; otherwise a pure hue is mixed with white and black. Missing `none` components resolve to their rendering defaults. Background colors and the `background` shorthand accept the function through their existing color consumers. `RenderOutputParity.HwbColorsNormalizeWhitenessBlacknessAndAlpha` checks both branches, missing components and alpha against an equivalent HSL color. This follows [CSS Color 4 §8](https://drafts.csswg.org/css-color-4/#the-hwb-notation) and keeps computed colors in relayout-owned style under **D4.5.1v4**. Computed-style serialization and interpolation that preserves missing components remain open.

Linear gradients retain a `to` corner direction until paint, where the painted rectangle's aspect ratio sets the angle. Raster backgrounds, vector paint, border images and text gradients share the gradient line calculation; its endpoints follow [CSS Images 3 §3.1](https://drafts.csswg.org/css-images-3/#linear-gradients). `RenderOutputParity.GradientCornerDirectionUsesPaintedBoxAspectRatio` checks the neighboring corners at the 50% stop in a 200×100 box. The `LinearGradient` descriptor remains relayout-owned under **D4.5.1v4**.

Radial and conic gradients now share center resolution for `at <position>` with side/center keywords, percentages and CSS lengths. Percentages are kept relative to the painted rectangle, while lengths remain absolute CSS pixels; both painters use the resulting center. `RenderOutputParity.GradientCentersResolveKeywordsPercentagesAndLengths` compares keyword versus percentage and length versus percentage forms in raster output and checks that explicit centers differ from the default. This follows [CSS Images 4 §3](https://drafts.csswg.org/css-images-4/#gradients) and keeps the gradient descriptors relayout-owned under **D4.5.1v4**. Full four-component position syntax, radial size keywords, ellipse geometry and vector conic output remain open.

Conic color stops now convert all CSS angle units to turns, preserve explicit negative positions, fix descending stops and interpolate missing interior stops. `repeating-conic-gradient()` wraps the painted angle by the first-to-last stop span, including when used through `background-image`; the longhand had omitted this function name. The first positioned color stop is no longer mistaken for a gradient prelude in conic or radial parsing. `RenderOutputParity.ConicAngleStopsSetRepeatPeriod` checks an angular-stop longhand against an equivalent percentage-stop shorthand, distinguishes repetition from a single conic gradient, and checks the radial first-stop form. This follows [CSS Images 4 §§3.3–3.5](https://drafts.csswg.org/css-images-4/#conic-gradients). Gradient stops and repeat state remain relayout-owned under **D4.5.1v4**. Vector conic output, full stop hints and color interpolation methods remain open.

The repeating radial raster path now samples the circle's color-stop period at each pixel and shares its display-list image allocation and clipping with the conic raster path. `RenderOutputParity.RepeatingRadialGradientUsesColorStopPeriod` checks that a 25% stop span produces a second red ring where a non-repeating gradient has already reached blue. The pixel buffer lives in the render display-list arena, while the radial descriptor remains relayout-owned under **D4.5.1v4**. Elliptical geometry, CSS-length stop conversion and vector repetition remain open under [CSS Images 4 §3.4](https://drafts.csswg.org/css-images-4/#repeating-gradients).

**Progress, 2026-10-03:** `:defined` now reads built-in status or the live custom-element registry, and registration schedules a broad recascade. `RenderOutputParity.DefinedSelectorRestylesAfterCustomElementRegistration` checks stylesheet restyling and DOM queries before and after registration. `:default` reuses the form's first-submitter traversal and tests checked/selected defaults; `:indeterminate` reads checkbox IDL state, unchecked radio groups and valueless progress, including live restyling (`RenderOutputParity.DefaultSelectorUsesFormDefaults`, `RenderOutputParity.IndeterminateSelectorTracksFormState`). The state and definition signals use document ownership under **D4.5.1v4**.

`:in-range` and `:out-of-range` now use the input value codec's parsed bounds and validity flags. Number input IDL values write live value state, and a control-value mutation requests a full recascade when value-dependent stylesheet selectors are present; this covers sibling and relational invalidation (`RenderOutputParity.RangeSelectorsTrackLiveNumericValue`). The value store remains document-owned under **D4.5.1v4**.

The DOM validity flags now come from one native calculation shared by the JS `ValidityState` wrapper and `:valid`/`:invalid` matching. Form and fieldset selectors scan their candidate controls, including external form owners. Native option traversal lets required selects and initial CSS use the same selectedness without a JS realm. `:placeholder-shown` reads the initial or live value directly. `:user-invalid` and `:user-valid` parse and match the control's user validity bit, which submission/committed change sets and reset clears. `RenderOutputParity.StaticValidityAndPlaceholderSelectorsPaint` and `RenderOutputParity.ValiditySelectorsUseInitialAndLiveConstraints` cover static paint, queries, submission/reset, and later value changes. Full HTML pattern syntax and other interaction routes remain to verify. The bit lives with the document-owned element under **D4.5.1v4**.

The existing broad structural/class mutation planner also restyles `:has()` after a child insertion or adjacent sibling class change (`RenderOutputParity.HasSelectorRestylesAfterChildAndSiblingMutation`); the DOM matcher tests retain attach/remove coverage.

`RenderOutputParity.DialogAndPopoverStateSelectorsRestyle` checks `:modal` after `showModal()` and `open` removal, and `:popover-open` after show/hide. Open and closed sibling styles paint separately, and DOM queries track both states. The separate dialog `close()` API gap in the support report remains outside this selector check.

`@namespace` now binds named and default type/universal selectors within each stylesheet. The shared namespace resolver uses element namespace identity for HTML, SVG, MathML and explicit null namespaces; DOM queries have no named-prefix context. Undeclared prefixes reject ordinary selector lists, while `:is()` and `:where()` discard only the invalid argument. `CssEngineParserTest.NamespaceRulesBindQualifiedTypeSelectors`, `NamespaceSyntaxAndRulePlacement`, and `NamespaceErrorsRespectFunctionalListRecovery`, `DomIntegrationTest.QualifiedTypeSelectorsMatchElementNamespaces`, and `RenderOutputParity.NamespaceQualifiedStylesheetSelectorsPaint` cover parsing, matching, queries, and paint. The namespace lookup arrays and selector fields use stylesheet-owned pools under **D4.5.1v4**.

Attribute selectors now distinguish named, null and wildcard namespaces. An unqualified attribute stays in the null namespace even when `@namespace` supplies a default for type selectors. Parsed qualified names resolve against their in-scope `xmlns` binding; live `setAttributeNS` writes a document-owned namespace record and retains a qualified renderer attribute instead of an XLink mirror. `CssEngineParserTest.AttributeNamespacesResolveIndependentlyOfDefault`, `DomIntegrationTest.AttributeNamespacesMatchQualifiedAndNullAttributes`, and `RenderOutputParity.NamespacedAttributesRestyleAndMatchLiveQueries` check syntax, static matching, live query state and SVG paint. The existing SVG DOM contract still passes. The records follow **D4.5.1v4**.

The explicit attribute `s` modifier now forces case-sensitive value matching even in a case-insensitive matcher (`DomIntegrationTest.ExplicitAttributeCaseFlagOverridesMatcherMode`). The remaining Water.css geometry mismatch is under investigation.

### P1 — finish the shared selector core

1. Correct `:nth-of-type()` and `:nth-last-of-type()` to count only same-type element siblings; implement `:nth-child(An+B of S)` and its last-child counterpart by filtering siblings with `S` before applying the formula. Treat comments correctly for `:empty`.
2. Parse and match relative `:has()` arguments (`>`, `+`, `~` and descendant) using the candidate element as the anchor. Integrate those dependencies with the existing mutation planner in [Radiant_CSS_Cascade.md](../radiant/Radiant_CSS_Cascade.md) §3.10; structural/sibling changes must restyle affected ancestors or fall back to a full recascade.
3. Implement `:lang()` using inherited language and `:dir()` using resolved direction. Give stylesheet `:scope` its document scope, while DOM queries keep their query root. Add `:any-link` and `:local-link` on the existing link/URL model.
4. Implement state-backed `:default`, `:indeterminate`, `:in-range`, `:out-of-range`, and `:user-invalid`, plus `:defined`, `:modal`, and `:popover-open`. Share the state source used by form/dialog/popover behavior and invalidate styles when it changes. Verify `:placeholder-shown`, `:valid`, and `:invalid` in static layout/render when their initial state is known.
5. Add a namespace context for `ns|E` and `|E`, tied to `@namespace` and element namespace identity. Keep `*|E` behavior. Implement the column combinator only after defining the table-column relationship it queries; avoid treating it as an ordinary sibling combinator.

**Exit:** Matched sets and specificity agree across stylesheet and DOM-query paths for the same tree and context. Static and live state tests assert the intended differences. Every new relational selector has an invalidation test after DOM mutation.

The `||` column combinator now parses as its own relation and matches `<td>`/`<th>` against `<col>` or `<colgroup>` slots using the HTML table model, including `span`, `colspan`, `rowspan`, row-group boundaries and nested left selectors. `DomIntegrationTest.ColumnCombinatorUsesTableSlotsAndLiveSpans` checks structural matches and changes to classes and spans; `RenderOutputParity.ColumnCombinatorStylesCellsAfterColumnMutation` checks DOM queries and live stylesheet paint. A stylesheet with this relation forces a full recascade after an attribute or structural mutation because its affected cells can lie outside the edited subtree. The occupancy list is temporary and released before matching returns, following **D4.5.1v4**. This uses [Selectors 5 §9.1](https://drafts.csswg.org/selectors-5/#the-column-combinator) and the [HTML table model](https://html.spec.whatwg.org/multipage/tables.html#forming-a-table) for column membership; Selectors 5 moved this combinator from Selectors 4 in its August 2026 draft. Other host-language grid associations remain unimplemented.

### P2 — connect pseudo-elements to their own consumers

1. Carry `::marker` declarations, including `color`, into marker layout/paint. Style `::selection` from the selection painter and `::backdrop` from the top-layer painter. Route `::file-selector-button` to a distinct control part so its declarations do not style the `<input>` host.
2. Verify `::slotted()` against real slot assignment and mutation. Add `::part()` only when exported part names and shadow-tree traversal are available. `::highlight()` needs a highlight registry and paint path; `::cue` needs the media cue model. Keep broad `::-webkit-*` acceptance limited to named compatibility aliases that map to a real part.
3. Defer `:visited` until there is a history source and a defined privacy-safe set of exposed styles. Treat `:fullscreen`, `:autofill`, `:playing`, and `:paused` as state-integration tasks; do not make them unconditional matcher cases.

**Exit:** Each pseudo-element writes to a separately testable generated/control/paint target. Host styles stay unchanged, including after live restyling.

**Progress, 2026-10-03:** `::marker` color is resolved from its own style tree into the relayout-owned marker property, then used by raster and SVG paint. Inherited/current color still uses the originating list item's paint color. `RenderOutputParity.MarkerColorPaintsSeparatelyFromListText` checks the marker's green color and the host text's red color in both SVG and PNG after a class mutation. `border-inline-width`/`-style`/`-color`, `border-block-style` and their missing single-side longhands are now catalogued. A shared validator accepts one or two axis values, rejects negative or percentage widths and mixed CSS-wide lists, and preserves earlier valid declarations. The shared logical-side mapper sends each start/end component to its physical edge under `direction` and `writing-mode`; `border-block-width`/`-color` now honor distinct start/end values too. `CssEngineParserTest.LogicalBorderPartsValidateOneOrTwoSides` covers grammar, and `RenderOutputParity.LogicalBorderPairsMapByDirectionAndWritingMode` checks RTL, vertical layout and single-side SVG paint. This follows [CSS Logical Properties 1 §4.5](https://drafts.csswg.org/css-logical/#border-properties) and stores computed border values in relayout-owned view props under **D4.5.1v4**.

The four logical corner radii now map the block and inline start/end pair to the existing physical `Corner` slots. They share value parsing and paint with physical radii and accept one or two non-negative length/percentage components and CSS-wide values. For `inherit`, the child first maps its logical corner to a physical corner, then copies that physical corner's computed parent value; a local Chromium headless-shell check confirmed this behavior when the parent's writing mode differs. `CssEngineParserTest.LogicalCornerRadiiValidatePhysicalValueGrammar` rejects unsupported syntax; `RenderOutputParity.LogicalCornerRadiiMapAndCompeteWithPhysicalCorners` checks LTR, RTL, vertical layout, mixed-writing-mode inheritance and a later physical override in SVG. `calc()` in a logical corner radius remains unsupported. This follows [CSS Logical Properties 1 §4.6](https://drafts.csswg.org/css-logical/) and keeps radii in relayout-owned border state under **D4.5.1v4**.
