# Radiant multiple views and paged-media implementation

**Status:** in progress, 2026-10-06. The complete publishing proposal remains the delivery scope; completion of the view model does not complete pagination.
**Design authority:** [Radiant_Layout_Paged_Media](../radiant/Radiant_Layout_Paged_Media.md), including multiple views, preview roots, page selection and book spreads.
**Formal linkage:** D4.5.1v4 (Radiant regions/pools and generation handles), D4.1.4v5 (allocator lifetime and single-writer publication), D5.3.3/D5.4.1 (precise callback/evaluator ownership), D7.1.2v2/D7.1.4v2 (resource layering and headless profiles). Geometry follows RSC1 and RSC6–RSC8 in [Radiant_Scale](../radiant/Radiant_Scale.md). No formal language ruling is changed.

## Delivery sequence

| Phase | Implementation and dependencies | Completion gate |

| P2: explicit CSS/style and layout context | Shared CSS inputs with per-view cascade destinations/environment; selected-view access in shared CSS/layout/paint algorithms; embedded default adapter | Real screen/print and narrow/wide layouts coexist over one DOM; reversed creation order is stable; no default-property swapping or semantic DOM cloning |
| P3: typed paged CSS | Typed `@page`/margin rules, break aliases, named/sided page templates and physical units | Registered cascade fixtures; invalid geometry errors; parsed/resolved/layout/paint support distinguished |
| P4: resumable main flow | Producer/policy contracts, block/inline continuations, paragraph alternatives, checkpoints, margins/decorations, nested fragmentainers, tables and admitted flex/grid contexts | Real text splits without skipped/duplicated ranges; nested scopes and changing widths resume correctly |
| P5: publishing composition | Footnote reservation/splitting, deferred floats/flushes, running content, counters, targets, TOC/leaders and convergence | Joint body/note/float/reference fixtures, rollback and diagnosed nonconvergence; non-DOM glue/penalty/policy fixtures |
| P6: output and entry points | Fragment-aware paint input, physical PDF page loop, glyph-position preservation, preview raster paint, export selection, opt-in options and A4 | Audit probe becomes three 240×360-point pages; PDF structure/raster checks; preview placement/filtering independent of export |
| P7: complete gate | Combined publishing corpus, limits, headless checks and release measurements | Required initial features pass together; focused and aggregate baselines reported separately; remaining platform/spec boundaries explicit |

P1 supplies geometry/presentation mechanisms for P6. P2–P4 now compose actual secondary block/inline views; P4–P6 remain partial. The CLI must not advertise complete publishing support before the remaining producer, continuation and composition gates pass. The real TeX/LaTeX producer is future work; extensibility contracts and their tests belong to this delivery.

## Current changes

- Added independent secondary-view storage while keeping `DomDocument::view_tree` as the default DOM-backed owner.
- Source state and occurrences share source identities and carry tree/generation handles. Source epochs reject stale layouts; resetting one tree invalidates only its handles.
- Added grouped-grid placement, physical range selection, facing-page preview, clip-based paint traversal and a complete physical-page visitor.
- Added per-view cascade queries, variable inheritance and explicit viewport/media/font contexts. Secondary styles and text fragments do not overwrite default-view properties. Existing length, display, font and margin-collapse helpers are shared.
- Added typed `@page` selectors and margin rules, named/sided/blank templates, physical paper sizes, percentage margins, modern/legacy break validation and `always` normalization. Page templates return to `auto` when the named source context ends.
- Added source-neutral box/glue/penalty, paragraph-alternative, flow-checkpoint and page-policy contracts. `typeset_page_plan()` lazily expands contributions, probes body/note/float reservations, retains legal candidate checkpoints and delegates selection/assembly to the policy. Every trial exit restores the provider; `typeset_page_commit()` restores only the chosen continuation and invokes commitment once. Hold/reinsert decisions remain provisional, with no shipout. The caller owns scratch and retains provider/policy/payload lifetimes until commit or abandonment, following D4.5.1v4 and D4.1.4v5. Producer checkpoints must cover expansion, marks, auxiliary queues and any state a failed commit changes. Native fixtures retain exact producer metrics beyond binary64 integer precision and test rejected, stale, failed, held, reinserted and budget-limited trials. HTML paragraph prefixes now use this planner, with region reservations and widow/orphan lookahead in their probe. The recursive HTML block driver still needs a whole-page provider and cross-block rollback; paragraph integration does not complete that gate.
- Added block/inline continuations with page-local occurrences, changed-width paragraph regeneration, widow/orphan lookahead, keep-inside and keep-with-following-lines. Selection precedes occurrence publication. Diagnostics record relaxed line minima/avoidance and reject an unplaceable fresh-page line without exhausting the page budget. Block padding, solid borders and flat backgrounds share edge normalization with note areas; `box-decoration-break: slice|clone` reserves only the edges owned by each occurrence. Specified content-box/border-box heights exclude repeated decorations from consumed content. Nested formatting contexts, complete margin/decoration rules, and richer shaping remain open.
- Added generated page-margin fragments, page/page-total counters and all sixteen margin positions. Automatic variable-axis sizing follows [CSS Paged Media 3 §5.3.2](https://www.w3.org/TR/css-page-3/#margin-dimension), using intrinsic ranges and the doubled side-box construction for a centered middle box. Full authored margin-box size/edge/font properties remain open. Margin-only totals resolve after body pagination against fixed margin regions.
- Added source-neutral immutable running marks in `typeset_marks.{hpp,cpp}`, including checkpoint/restore and producer-native typed payloads. The CSS adapter assigns named strings at committed source placement, selects `first`, `start`, `last` and `first-except`, carries state through blank and continuation pages, and anchors hidden assignments without consuming body space. Comma-separated assignments, `content()`/`content(text)` and attributes work; formatted running elements retain block/inline structure and original source styles in separate repeated fragments. Running strings also consume immutable source-counter snapshots and cached `content(before)`/`content(after)` text. Richer running formatting remains open. Selection of formatted elements follows [CSS GCPM 3 §1.2](https://www.w3.org/TR/css-gcpm-3/#running-elements). Selection follows [CSS GCPM 3 §1.1](https://www.w3.org/TR/css-gcpm-3/#named-strings). Trial restoration is tested in the source-neutral store; full HTML body/note rollback is still pending.
- Added source-neutral region trials in `typeset_regions.{hpp,cpp}`. Minimum legal prefixes reserve space before distributing spare capacity. Rejected trials leave the queue unchanged; version checks reject stale commits. Native payloads and exact metrics survive splits. The CSS adapter publishes chosen auxiliary fragments only after body selection; closing declared extents/decorations participate in the final reservation, with a diagnostic if they would overlap the regions. Full body/region rollback remains required.
- Page-level footnotes support multiple styled notes, source-order calls/markers, splitting, deferred automatic notes and note-only continuation pages. `::footnote-call` and `::footnote-marker` have independent computed styles and generated content, including built-in counter formats, fonts, colors and authored vertical alignment. Hiding a call retains its source anchor. `line` moves a required atomic note with its call. `block` preflights the paragraph prefix through its required note anchors before publishing any paragraph line or running mark, moving the paragraph start if the joint reservation fails. Soft line minima may relax only after the required note has been admitted; an impossible fresh-page reservation stops without publishing an edition. This implements the bounded paragraph-start case of [GCPM 3 §2.8](https://www.w3.org/TR/css-gcpm-3/#footnote-policy), a working draft. A block-note prefix that itself exceeds a fresh page remains unplaceable; complete multi-page block checkpoints, default superscript font variants, page/source resets, column attachment and richer formatting remain required.
- Typed `@footnote` areas share the page-rule cascade, including repeated rules and page selectors. Supported area properties are `max-height`, `box-sizing`, padding, solid border widths/styles/colors, flat background color and bottom attachment. Anonymous area boxes own normalized boundaries in the selected view arena, following D4.5.1v4 and D4.1.4v5. Their edges participate in admission and use the existing boundary painter. Area limits are ignored on note-only pages, but retained when floats share a continuation page. A zero body-page budget can defer an automatic note without losing its call. Full area margin/font/dimension, gradient, radius and other border styles remain open. Behavior follows [GCPM 3 sections 2.4 and 2.8](https://www.w3.org/TR/css-gcpm-3/#footnotes), a working draft.
- HTML full-width `float: top|bottom; float-reference: page` materials share body/note reservation. Top floats translate the already selected body geometry; bottom floats sit above notes. Atomic floats can defer when space is exhausted, and same-edge clearance starts a fresh region. Positive `float-defer` currently sets an earliest page; forced body breaks preserve that deferral. This is a bounded draft subset: end-relative/clamped deferral, narrow and column floats, cross-kind ordering and explicit flush boundaries remain required.
- Publishing names preserve case in parsed name positions, including keyword collisions such as `Red` versus `red`; ordinary CSS keywords remain case insensitive. Parser and actual running-string/named-page composition fixtures reproduce the original collision and verify the grammar-based repair.
- Source counters apply reset, increment and set in logical source order, then copy active nested bindings into immutable per-view snapshots. Source `::before`/`::after` fragments retain their semantic element and their own styles without adding DOM children. Block pseudos now use the existing block/paragraph producer, preserving their own padding, borders and backgrounds across page placement; inline pseudos retain inline flow. Paragraph continuation and repeated headers never re-enter counter scopes. Nested quotes share source-order depth. Built-in counter formats and `counter()`/`counters()` work in body pseudos and running strings. Reversed counters, custom counter styles, list markers, reserved page/note declarations and body-local page bindings remain diagnosed or unfinished. Ordering follows [CSS Lists 3 section 4](https://www.w3.org/TR/css-lists-3/#auto-numbering); element resets reach following siblings and remain bounded by the parent under [section 4.4](https://www.w3.org/TR/css-lists-3/#counter-scopes).
- Added source-neutral target stores and exact-signature convergence checks in `typeset.{hpp,cpp}`. The CSS adapter supports local-fragment `target-counter()`, `target-counters()` and `target-text()` in body generated content and page furniture. Text selectors admit `content`, `before` and `after`; attributes admit plain and legacy typed `attr(href url)`. The first duplicate HTML ID wins. Page references use first committed source placement or the placed note/float region. Missing IDs, external URLs and unplaced page targets produce diagnostics; provisional zero/empty seed bindings are never published. Complete view passes compare retained target values, generated text and fragment/page decisions, rejecting repeated nonconverged states and configured pass-budget exhaustion. Final anchor bindings are view-owned and queryable through `layout_secondary_target()`, following D4.5.1v4 and D4.1.4v5. Full URL fragment decoding, first-letter/marker extraction, logical page-counter resets and incremental prefix reuse remain open. Reference syntax follows [CSS Generated Content 3 section 2.6](https://www.w3.org/TR/css-content-3/#cross-references), a working draft.
- Added body-pseudo leaders as source-neutral ordered glue with immutable glyph-pattern payloads. Dotted, solid, space and string patterns expand between adjacent text and an end-aligned suffix; multiple leaders share spare width. Patterns tile from the line end edge, omit newline characters and use the existing glyph/font lowering. Repeated glyphs have a view-wide contribution budget; a leader-only line is diagnosed. Authored HTML TOC/list entries can combine these items with target references. Text-only running-string/note evaluators and margin leaders remain unsupported; the draft's fallback rebreak for a too-tight aligned pattern still needs a paragraph policy. These are explicit subset boundaries, not full [CSS Generated Content 3 section 2.5](https://www.w3.org/TR/css-content-3/#leaders) conformance or automatic semantic-outline extraction.
- Consolidated generated text evaluation for default pseudo content and secondary page content. Strings use `StrBuf`, eliminating the old fixed 512-byte concatenation limit; attributes, quotes and counter callbacks share the evaluator. This changes default browsing code and requires aggregate regression gates.
- Added physical secondary-view PDF export, explicit export selection, per-page lowering/backdrop reset and 96px-to-72pt conversion. Preview filtering/placement/scale never changes physical page export. Positioned glyph runs share font-local outline lowering across PDF, SVG and raster. Current positioned PDF text is outlines; embedded searchable font output is not implemented.
- Registered all model/layout tests in the View Reuse runner and its focused suites in `make test-radiant-baseline`. Added the experimental `render --paged` path for HTML/Lambda input and PDF output. It uses the settled loader DOM, resolves an independent print view and exports physical pages; A4 fallback is independent of viewport flags. File-level regressions cover CSS sheet sizes, raster scale, A4, continuous-export compatibility, post-script break styling and actionable errors. Replaced content, flex/grid/table/list contexts, columns, positioned content and ordinary inline floats now require their own producers/policies rather than being silently flattened; hidden subtrees do not require those producers.

- Secondary font-family resolution uses the shared family-list resolver and the selected tree property pool, following D4.5.1v4 and D4.1.4v5. Comma-separated fallback families remain separate, while multiword names remain joined. File-based secondary layout does not require creation of the default browsing view. Retained sibling editions and the source font properties stay independent.
- Added owned in-memory and PNG root snapshots using the existing paint IR and display-list raster backend. The selected preview arrangement supplies bounds, placements and filtering; output density does not recompose physical pages or overwrite the DOM/default view. Shared display-list snapshot replay also serves SVG export captures. Embedding callers own `rdt_engine_init()`/`rdt_engine_term()`; returned surfaces own their pixels and use `image_surface_destroy()`. A rendered-preview regression exposed transform scopes being tagged as raster no-ops, stacking every page at the origin. Raster lowering now composes nested scopes with local path/image/clip/glyph transforms, maps logical effect bounds before pixel reservation, and leaves source commands intact for later PDF/SVG consumers. Grid/book pixel and lifetime checks pass. Output density is applied once to logical paint before lowering; replay consumes physical display-list coordinates.
- Added `render_secondary_page_snapshot()` for direct physical-page thumbnails, independent of preview selection, scale, gaps or book partners. Independent `RenderPageSnapshotCache` instances use explicit entry/retained-surface-byte limits and LRU eviction. Keys include page tree/generation/node handles, source epoch, environment resource generation, font resource generation, density and backdrop; presentation changes preserve cache hits. A shared surface-size validator rejects overflow or a surface exceeding the cache budget before allocation. Caches own raster copies and retain no source-tree, font or arena pointers between calls, so source-view destruction does not invalidate already rendered pixels. Cached surfaces are borrowed until the next cache mutation; direct snapshots remain caller-owned. Derived roots with retained page instances/display lists and file-level thumbnail/preview entry points remain future steps within P6.
